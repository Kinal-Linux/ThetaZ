# ThetaZ / "C~" — Wow64 (running 32-bit Windows apps on 64-bit)

Modern Wine ships a full wow64 implementation: a 64-bit tree can run 32-bit
Windows apps with **no 32-bit Unix code** (all unix work is 64-bit).

## Components

- `dlls/wow64cpu/` — the CPU transition layer.
  - `struct thunk_32to64 { syscall_thunk; unix_thunk; }` — 32-bit callers jump into
    these asm thunks, which switch to 64-bit mode, execute the 64-bit syscall /
    unix call, and return to 32-bit.
  - `cpu.c` also translates a 64-bit exception CONTEXT into the 32-bit WOW64_CONTEXT
    when a 32-bit app faults (`KiUserExceptionDispatcher` in 32-bit ntdll is
    reached from the 64-bit exception handler via wow64).
- `dlls/wow64/` — API translation (32-bit structs → 64-bit) for ntdll syscalls:
  file.c, process.c, registry.c, security.c, sync.c, syscall.c, system.c,
  virtual.c. Uses `struct32.h` (32-bit versions of structures) and a set of
  conversion helpers. Its `.spec` maps the 64-bit syscall numbers and forwards.
- `dlls/wow64win/` — the NtUser/NtGdi (win32u) wow64 translation: user.c, gdi.c,
  syscall.c — 32-bit user/gdi calls get translated and re-dispatched.
- `dlls/wow32/` — 32-bit helpers (`wow32.dll`).
- In the prefix: `system32/` holds 64-bit, `syswow64/` holds 32-bit dlls. The PE
  loader maps both; `load_wow64_ntdll()` in ntdll/unix/loader.c loads the 32-bit
  ntdll.dll and wires its `LdrSystemDllInitBlock`.

## Flow for a 32-bit syscall

```
32-bit app → syswow64\ntdll.dll (NtXxx stub)
  → wow64cpu thunk (syscall_thunk)  # switch to 64-bit
  → 64-bit ntdll __wine_syscall_dispatcher
  → wow64.dll translation (arg structs 32→64)
  → unix syscall implementation (64-bit)
  → translate reply back, switch to 32-bit, return
```

## Enabling

- `WINEARCH=wow64` (or `--enable-archs=i386,x86_64` build). Proton sets
  `WINEARCH=wow64` when `PROTON_USE_WOW64=1`.
- ntdll/unix/loader.c `start_main_thread()` → `load_wow64_ntdll(machine)`.
- The 32-bit TEB lives inside the 64-bit TEB (`TEB->WowTebOffset`); `get_wow_teb()`
  in unix_private.h.
